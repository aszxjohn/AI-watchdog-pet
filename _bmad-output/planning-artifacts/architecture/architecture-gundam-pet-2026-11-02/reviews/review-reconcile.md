# Spine × memlog 對帳結果

- 對象：`ARCHITECTURE-SPINE.md`（AD-1～AD-15）對 `.memlog.md`（L1～L73，`updated: 2026-11-03T10:08`）
- 方法：memlog 每一行逐條比對；後面的條目覆蓋前面的（例：L34 assumption 被 L38 取代、L23 被 L72 確認、L50 question 被 L61 取代）。參考 Demo 分支 README 判斷 spine 多出來的內容是「從 Demo 帶過來」還是「作者自己加的」。
- 只讀，沒有改任何檔案。

## 結論

大方向都有落地：8 狀態與優先序、完全唯讀偵測、轉接器→判斷器、`done` 過場、繪圖指令＋單一 PixiJS、世界歸舞台、4 種跨包事件、4 項固定參數、兩層取值、`.awpet`／AI Watchdog Pet、技術棧版本，以及 L71～L73 確認的三個 assumption。

問題集中在三類：

1. **Demo 保留功能只剩名字**：「名牌與標記」在 spine 只是一個開關（AD-11），功能本身沒有規則；AD-6 定的「包宣告的後備演出」，在 AD-13 的 manifest 欄位裡找不到。
2. **作者自己加的規則**：AD-12 把「包內勾選角色」和「加入池子」當成兩個開關取交集；AD-15 的 demo 轉接器設計；AD-10 規定同包互動「不經過舞台」。
3. **未定案的事被寫成已定**：AD-7 沙盒分層在 memlog 是「研究建議，使用者未反對，需原型驗證」，spine 標成 [ADOPTED]；匯出不帶使用者調整；Copilot 只做一種。

嚴重度標記：🔴 會影響實作方向／契約，🟡 應補，⚪ 小項。

## (A) 使用者決定被漏掉或改弱

### A1 🔴 「名牌與標記」只剩一個顯示開關，功能本身沒寫

- **memlog**：L40「保留的畫面行為：…在畫面裡遊走；**名牌與標記**」；L43 固定參數「名牌與標記顯示」

## (B) spine 有、memlog 沒有（作者加的，需使用者確認）

### B1 🔴 池子變成三重交集，同一個開關被拆成兩個

- **memlog**：L43 固定參數「加入池子（啟用）」；L44「也可在包內勾選哪些角色進池子」
- **spine**：AD-12（L140）定成「勾選上場的包 ∩ **包內勾選的角色** ∩ **固定參數『加入池子』為開**」；AD-3（L74）把「池子勾選」和「固定參數」分成兩欄存。
- **問題**：memlog 的兩句很可能是同一件事（每個角色一個「加入池子」勾選）。拆成兩個開關，UI 和設定檔會出現兩個意思相同的勾選框。
- **建議**：請使用者確認。建議合併成「池子＝勾選上場的包 ∩ 該角色的『加入池子』固定參數為開」。

### B2 🔴 AD-15「展示／示範走同一條管線（假 demo 轉接器）」

- **memlog**：L41 只有「保留的工具：…展示／示範模式」，沒討論怎麼做。
- **spine**：AD-15（L154～L158）整條是作者加的，而且把展示和示範合成一個轉接器。
- **問題**：Demo 的兩種模式不一樣。示範模式是 8 個假 session 輪換，適合做成轉接器。展示模式是畫面上只留一隻，可以手動切狀態、**換角色**、重播進場，角色編輯頁的「在畫面上預覽」也靠它。「指定角色」會跟 AD-12 的池子分配規則衝突。
- **建議**：保留「示範＝demo 轉接器」。展示模式另外寫一條：「可指定角色、繞過池子分配，但仍走同一個判斷器與世界」。兩者都請使用者確認。

### B3 🟡 AD-10「同包互動在同一沙盒、不經過舞台」

- **memlog**：L26 只說同包可以有自訂特殊互動；L33 規定位置、移動、碰撞歸舞台。
- **spine**：AD-10（L128）加了「包內特殊互動由包自己處理，**不經過舞台**」。
- **問題**：同包角色要互動（例如走向對方、對射），就需要知道彼此位置並移動。但位置和移動歸舞台，「不經過舞台」做不到。L60／AD-9 的繪圖指令也有「位置」，跟世界擁有位置的規則重疊，應該說明這是相對錨點的偏移。
- **建議**：改成「同包互動的判斷邏輯由包自己寫；需要的己方角色位置由舞台唯讀提供，移動透過舞台 API 請求」，並說明繪圖指令的位置是相對偏移。

### B4 🟡 AD-11 參數型別限 `bool`／`int`／`number`／`choice`，以及孤兒覆蓋值的處理

- **memlog**：沒有討論參數型別。L20 只說下半部是包宣告、「開放給舞台修改」的參數。
- **spine**：AD-11（L134）限定四種型別；另外規定「包更新後已不存在的參數，覆蓋值保留但不套用」。
- **問題**：Demo 另有 `asset` 型別（例如換子彈圖），以及 `user: true/false`（宣告了但不開放給使用者）。spine 沒說明就拿掉了這兩項。
- **建議**：請使用者確認型別清單、要不要 `asset`，以及要不要「開放／不開放」旗標。孤兒覆蓋值的規則也一起確認。

### B5 🟡 舞台層級的滑鼠互動和選單，memlog 沒討論過
