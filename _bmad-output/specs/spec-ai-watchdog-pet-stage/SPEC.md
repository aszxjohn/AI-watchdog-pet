# AI Watchdog Pet 舞台

## Why

願景加上痛點。使用者同時開好幾個 AI coding session（Claude Code、Codex、Gemini、Cursor、Copilot），需要不切視窗就知道哪個 session 在等自己。舊版 Demo（macOS Swift、鋼彈力天使）證明了「每個 session 一隻桌寵，依狀態演出」可行，但角色專屬程式和系統纏在一起，只能跑在 macOS、只認 Claude Code。這次重做主程式「舞台」：舞台自己就能完整運作，角色做成可匯出匯入的角色包，任何系列（鋼彈、寶可夢……）都能加進來而不用改舞台，同時支援多種 AI 工具與 Windows。

## Capabilities

- **CAP-1**
  - **intent:** 舞台以唯讀方式偵測 Claude Code、Codex CLI、Gemini CLI、Cursor、Copilot CLI 的 session，並把每個 session 歸成 8 種狀態之一。
  - **success:** 每種工具各開一個 session 都會出現在畫面上。確定的狀態改變後 2 秒內反映在畫面上（Cursor 例外：它以 step 為單位寫紀錄，延遲數秒到數十秒）。工具執行超過 10 秒沒結束、又讀不到批准訊號時，推測為「要你批准」。執行前後比對各工具資料夾的雜湊，完全不變。Copilot CLI 必須用真實 session 驗證過才算完成。
- **CAP-2**
  - **intent:** 每個追蹤中的 session 從池子分到一隻角色；池子用完前畫面上不重複，session 結束後角色放回池子。
  - **success:** session 數 K 不超過池子大小時，畫面上 K 隻角色各不相同；結束一個 session，它的角色離場，之後能再被分配。
- **CAP-3**
  - **intent:** 使用者可以指定哪些 session 要顯示、哪些釋放不追蹤，之後也能改回來。
  - **success:** 被釋放的 session 收回角色，但仍留在管理清單；改回顯示後重新分到角色。
- **CAP-4**
  - **intent:** 角色在使用者選定的一個螢幕上遊走，畫布透明、置頂，並且滑鼠穿透。
  - **success:** 點畫面空白處，操作的是底下的視窗；只有游標在角色身上時，畫布才接收滑鼠。
- **CAP-5**
  - **intent:** 使用者可以用左鍵把角色「捏起來」拖到別處，放開後角色從放下的位置直接恢復遊走。
  - **success:** 拖曳中角色跟著游標、不會中途掉落；包有實作就演被捏起來的動作，沒實作就照原樣被拎著走。
- **CAP-6**
  - **intent:** 右鍵角色開選單（這個角色的編輯頁、管理 session、暫停／顯示）；app 入口在 macOS 選單列與 Windows 系統匣。
  - **success:** 三個選單項各自打開對應功能；Dock 與工作列上沒有 app 圖示。
- **CAP-7**
  - **intent:** 舞台在每隻角色上方顯示 session 顯示名稱和狀態標記；推測出來的狀態用另一種標記樣式；可以逐角色關閉。
  - **success:** 同一狀態的「確定」與「推測」兩種標記看得出差別；關閉後名牌和標記都不畫。
- **CAP-8**
  - **intent:** 使用者在角色編輯頁調參數：上半部是舞台的固定參數（大小、加入池子、遊走偏好、名牌與標記顯示），下半部依角色包宣告自動產生（開關、整數、數字、選項、換圖）。舞台有設定就用舞台的值，沒有就用包的預設值；調整只存在舞台，以角色為單位。
  - **success:** 新角色包不用寫任何介面程式，編輯頁就出現它宣告的欄位；重新匯入同一個包之後，先前的調整仍在。
- **CAP-9**
  - **intent:** 使用者選擇哪幾包上場；每個角色只有一個「加入池子」開關，屬於舞台設定，在編輯頁和包管理頁看到的是同一個值。
  - **success:** 關掉某角色的開關後，它不再被分配；兩個頁面顯示的值永遠一致。
- **CAP-10**
  - **intent:** 使用者可以匯入、匯出 `.awpet` 角色包。匯入時，危險或不相容的包會被拒絕並說明原因；匯出只包含角色包本身。
  - **success:** 含 `..` 路徑、超大圖片、API 版本不相容的測試包都被拒絕並顯示原因；匯入同 id 的包要確認才替換，安裝失敗會回復舊版；匯出檔不含使用者的調整。
- **CAP-11**
  - **intent:** 每隻角色依 8 狀態演出。包沒做的狀態，先演包宣告的後備演出，沒有後備才演舞台的佔位演出；「做完了」是過場，預設 5 秒後轉成「等你回覆」；預設 5 分鐘沒有動靜就轉「休息中」。這些秒數都可以在舞台設定裡調。
  - **success:** 只實作部分狀態的測試包，在其他狀態演後備或佔位；每一輪結束先顯示 `done` 5 秒，之後轉 `waiting`；5 分鐘沒有新事件就轉 `idle`。
- **CAP-12**
  - **intent:** 不同包的角色透過五種通用互動彼此反應：被擊中、靠近／碰撞、進場／離場、狀態廣播、被捏起來。舞台提供通用飛行物件，包可以用自己的物件；沒指定或舞台不認得時，改丟一個隨機的通用物件。命中由舞台判定。
  - **success:** A 包射中 B 包的角色時，B 收到 `hit`；沒處理 `hit` 的包沒有反應，也不報錯；指定了不認得的物件時，仍然會丟出通用物件。
- **CAP-13**
  - **intent:** 同一包的角色之間可以有包內自訂的特殊互動。
  - **success:** 一個多角色的測試包，能讓兩隻己方角色對彼此的事件做專屬反應。
- **CAP-14**
  - **intent:** 包可以請自己的角色停下、恢復遊走或轉向，但不能指定位置。
  - **success:** 包請求停下後，角色停在原地；使用者把遊走設成關閉時，包的恢復遊走請求無效。
- **CAP-15**
  - **intent:** 角色包只能做表演：碰不到檔案、網路、系統指令、對話內容、其他包和舞台設定，出錯也只影響自己。當掉時自動重啟，最多 3 次，仍失敗就視同停用並顯示原因。包被停用或移除、角色消失時，畫面上的角色換成池子裡的其他角色。
  - **success:** 惡意測試包的連網和讀檔嘗試全部失敗；讓一包當掉時，其他角色照常演出；第 4 次失敗後，該包被標為失敗，它的角色被換掉。
- **CAP-16**
  - **intent:** 示範模式用假 session 輪播 8 種狀態，並照池子分配角色；展示模式可以指定任何角色和狀態，不存檔、不佔池子名額；編輯頁的預覽用的就是展示模式。
  - **success:** 沒有任何真 session 時，也能看到每種狀態的演出；展示模式指定的角色不影響真 session 的分配。
- **CAP-17**
  - **intent:** 舞台留運行紀錄，並保護設定檔不被默默蓋掉。
  - **success:** 紀錄每小時一個檔，只留 24 小時；放進一個壞掉的設定檔後，app 正常啟動、改用預設值，原檔以 `.broken` 名稱保留。
- **CAP-18**
  - **intent:** 沒有安裝任何角色包時，舞台的偵測、面板、管理 session 都照常運作。
  - **success:** 全新安裝啟動後，畫布是空的，面板能列出偵測到的 session。

## Constraints

- 對 AI 工具完全唯讀：不寫入任何工具的檔案或設定，不裝 hook，也不執行任何會寫入工具資料夾的指令，例如 `claude agents --json`（AD-4）。
- 舞台程式裡不能有任何角色、系列名稱或角色專屬邏輯（AD-1）。
- 角色包是沙盒裡的程式外掛，只能透過舞台 API 溝通；`'unsafe-eval'` 只開在沙盒內（AD-7）。沙盒原型關卡通過前，不實作沙盒相關模組。
- 狀態固定為 8 種英文代碼，由舞台定義。包只收到這 8 種狀態和 session 顯示名稱，收不到原始的工具訊號（AD-6）。
- 世界歸舞台管：位置、移動、碰撞、飛行物件都由舞台負責；包只回傳繪圖指令，由舞台用單一畫布統一畫（AD-9、AD-10、AD-17）。
- 使用者的調整只存在舞台設定，以角色為單位，不寫進角色包（AD-11）。
- 角色包要宣告 API 版本，不相容的包在安裝和載入時就被拒絕（AD-8）。
- 平台以 macOS 和 Windows 為主；Linux 次要，只做整窗穿透。第一版只用一個螢幕（AD-14、AD-26）。
- 第一版完全不連網（AD-26）。
- 判別值一律用英文代碼，中文只出現在顯示層。
- 技術棧依架構規約的 Stack 表。

## Non-goals

- 製作任何角色包（美術、素材管線、特定角色）。
- 安裝 hook 或修改任何 AI 工具的設定。
- 第一版的角色包沒有聲音、收不到滑鼠事件、拿不到牆上時間。
- 匯出時附帶使用者的調整。
- 跨螢幕的世界、Copilot 的 VS Code 版（列為延後）。
- 移植 Demo 的程式碼（Demo 只當行為參考）；不保留離線連拍。
- 自動更新、角色包市集等需要連網的功能。

## Success signal

- 同時開著 Claude Code 和 Codex 的 session、裝了兩個不同系列的測試包時：每個 session 都有自己的角色在透明畫布上依狀態演出；能把角色拖走、調參數、匯入匯出包；惡意測試包連不到網路也讀不到檔案，當掉時不影響其他角色；各 AI 工具的設定檔雜湊都沒變。
